# 233战法自动扫描系统

基于A股"233战法"的自动化扫描与可视化系统。通过分层筛选，在资金开始进攻后寻找当日确定性更高的短线机会。

## 核心理念

> 不预测涨停，而是在资金已经开始进攻之后，通过层层筛选，寻找当天确定性更高的机会。

- **2个核心原则**：板块优先于个股；跟随而非预测
- **3个筛选标准**：股性活跃（涨停基因）、市场辨识度（成交额/换手）、量价结构（红肥绿瘦+放量）
- **3个确认信号**：板块确认、龙头确认、买点确认（四条件共振）

## 功能概览

| 模块 | 功能 | 触发时间 |
|------|------|----------|
| 盘前筛选 | 涨停基因 → 量价结构 → 辨识度评分 → 核心股池 | 08:30 |
| 盘中扫描 | 板块确认 → 龙头确认 → 买点确认（四条件共振） | 09:25 / 10:30 / 13:00 / 14:30 |
| 回测 | 按日重建盘前股池 → 模拟买卖 → 胜率/回撤/评分区分度/参数扫描 | 手动 |
| Web可视化 | 股池查看、扫描结果、运行日志、参数配置、历史记录、回测 | 浏览器访问 |
| 历史存档 | 每日股池及每次盘中扫描结果自动存档为JSON | 扫描完成后自动 |

## 快速开始

### 环境要求

- Python 3.9+
- macOS / Linux

### 安装

```bash
git clone git@github.com:shuxinlei/233.git
cd 233
pip install -r requirements.txt
```

### 运行

**方式一：自动调度模式（全天运行）**

```bash
python main.py
```

程序会在交易日自动执行：
- 08:30 盘前筛选
- 09:25 / 10:30 / 13:00 / 14:30 盘中扫描
- 15:30 自动结束

**方式二：手动运行单次任务**

```bash
python main.py --mode pre        # 只跑盘前筛选
python main.py --mode intraday   # 只跑盘中扫描
```

**方式三：Web可视化**

```bash
python app.py
```

浏览器打开 http://127.0.0.1:5555 ，可在页面上手动触发筛选/扫描/回测、查看结果、调整参数、浏览历史记录。

**方式四：回测**

```bash
python backtest.py --start 20260818 --end 20260904
```

参数扫描（同一段样本上横向对比某个参数的不同取值）：

```bash
python backtest.py --start 20260818 --end 20260904 --sweep RED_GREEN_RATIO=1.0,1.5,2.5
```

## 筛选流程

### 盘前筛选（核心股池构建）

```
涨停池数据(近30日)
    ↓ 涨停次数 ≥ 阈值
涨停基因池
    ↓ 红绿比 ≥ 1.5 + 量比 ≥ 1.2 + 换手 ≥ 3%
量价筛选池
    ↓ 涨停基因40% + 流动性30% + 量价30% 加权评分
核心股池 Top50
```

### 盘中扫描（三重确认）

```
板块确认: 概念+行业板块涨幅排名 → 取前8
    ↓
龙头确认: 核心股池中 涨幅≥5% + 量比≥1.5 + 换手≥5%
    ↓
买点确认: 四条件共振
    ├─ 板块在涨 (≥2%)
    ├─ 核心在动 (≥5%)
    ├─ 量能在放 (量比≥1.5)
    └─ 股价突破MA5
```

## 策略参数

所有参数在 `config.py` 中集中管理，也可通过 Web 页面实时调整：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `PRE_MARKET_TIME` | 08:30 | 盘前筛选触发时间 |
| `SCAN_TIMES` | 09:25/10:30/13:00/14:30 | 盘中扫描时间节点 |
| `ZT_HISTORY_DAYS` | 30 | 涨停基因回看交易日数 |
| `ZT_MIN_COUNT` | 1 | 最少涨停次数 |
| `RED_GREEN_RATIO` | 1.5 | 红肥绿瘦最小比值 |
| `VOLUME_RATIO` | 1.2 | 量比最小值 |
| `TURNOVER_MIN` | 3.0% | 最低换手率 |
| `POOL_SIZE` | 50 | 核心股池大小 |
| `TOP_SECTOR_COUNT` | 8 | 取前N个板块 |
| `STOCK_RISE_MIN` | 5.0% | 龙头确认最低涨幅 |
| `STOCK_VOLUME_RATIO` | 1.5 | 龙头确认最低量比 |
| `PV_SCAN_MAX` | 200 | 涨停基因池过大时取前N只做量价筛选 |
| `EXCLUDE_SEALED_LIMIT_UP` | True | 封板状态不计入可介入与四条件共振 |
| `FAILED_TASK_COOLDOWN_SECONDS` | 60 | Web 任务失败后的冷却（成功走各自的完整冷却） |
| `BT_EXIT_MODE` | next_open | 回测出场方式 |
| `BT_COST_PCT` | 0.2% | 回测双边交易成本 |
| `BT_MAX_OPEN_GAP` | 9.5% | 开盘涨幅超过该值视为一字板买不进 |
| `BT_TOP_N` | 0 | 回测每日只取评分前N只，0=整个股池 |

## 历史数据

每次盘前筛选和盘中扫描完成后，自动存档到 `history/` 目录；接口原始数据和规则参数同时写入 `history/market_data.db`：

| 文件 | 内容 |
|------|------|
| `YYYYMMDD_pool.json` | 当日核心股池（含代码、名称、板块、评分等） |
| `YYYYMMDD_scan_HHMM.json` | 盘中扫描结果（含四条件共振状态） |
| `market_data.db` | 涨停池、日K、实时行情、板块、板块成分股及策略运行参数快照 |

通过 Web 页面「历史记录」Tab 可查看所有存档，左侧列表选择，右侧展示完整数据表格。

盘前筛选支持 `build_stock_pool(as_of_date='YYYYMMDD')`，只使用目标日前已完成交易日的数据，避免回测时把当天收盘结果带入盘前决策。

## 回测

`backtest.py` 回测**盘前股池**：按日重建股池（只用当日之前已收盘的数据）→ 模拟买卖 → 输出评估指标。

### 为什么只回测盘前

盘中扫描依赖两项历史上取不到的数据：

- **板块的盘中实时涨幅** —— AkShare 的板块接口只给日线，拿不到某个历史日期 10:30 时的板块涨幅
- **当时的板块成分股名单** —— 成分股接口只返回当前名单，历史成分无从还原

所以盘中回放只能等实盘运行把 `history/market_data.db` 的快照攒起来。而盘前这一层完全可回测，且所有可调参数（涨停基因、红绿比、量比、换手、评分权重、池大小）都在这一层。

### 交易假设

| 项 | 规则 |
|---|---|
| 入场 | 一律**当日开盘**买入（盘前选股，开盘执行） |
| 出场 | `next_open` 次日开盘卖（默认，T+1 最短合法持有，日期不重叠）<br>`next_close` 次日收盘卖<br>`nday_close` 第N个交易日收盘卖<br>`same_close` 当日收盘卖（T+0，A股做不到，仅作信号质量参考） |
| 买不进 | 开盘涨幅 ≥ `BT_MAX_OPEN_GAP` 视为一字板，跳过该笔 |
| 成本 | `BT_COST_PCT` 双边一次性扣除（佣金+印花税+过户费+滑点） |
| 组合 | 每日等权买入当日股池，按入场日聚合成组合日收益 |

### 输出指标

- **交易统计**：笔数、胜率、平均/中位收益、平均盈亏、盈亏比、最好最差单笔
- **组合表现**：累计收益、年化（样本≥20日才给）、最大回撤、夏普、日胜率、对基准超额
- **评分区分度**：按标的在当日股池中的排名分位分组看收益。评分若真有区分度，靠前分位应明显更好 —— 这是检验评分权重的核心视图
- **数据覆盖**：每个回测日的涨停池数据是否齐全（见下）
- **跳过的信号**：分原因统计（买不进 / 停牌 / 区间末尾缺卖出K线）

结果存档到 `history/backtest/*.json`（含逐笔交易），摘要同时写入 `market_data.db` 的 `strategy_runs`，附当次参数快照。

所有上游请求共享进程级限频器，默认两次请求至少间隔 `0.5` 秒、每分钟最多 `90` 次；缓存命中不会触发请求。Web 任务还有触发冷却：**成功后**盘前筛选默认 30 分钟、盘中扫描默认 60 秒、回测默认 5 分钟；**失败后只冷却 60 秒**（`FAILED_TASK_COOLDOWN_SECONDS`），避免一次网络抖动把盘前锁到错过当天扫描窗口。重复触发返回 `429` 和剩余等待秒数，`/api/status` 也会给出每个任务的 `cooldown_remaining`。

日K快照按「代码+区间」缓存，并用抓取时间校验覆盖：若快照是在请求区间结束日当天抓的，那天的K线可能还没发布，快照会被判为非最终版并重取 —— 否则会拿到一份声称覆盖到某日、实际缺最后一根的帧。

最终失败（重试过程只记录一条）会写入 `history/errors/YYYYMMDD.jsonl`。任务结束时自动更新异常汇总，也可运行 `python error_monitor.py --date YYYYMMDD` 或访问 `/api/errors/report?date=YYYYMMDD` 查看按接口、异常类型和错误模式聚合的日报。

### 数据可回溯范围（重要）

`stock_zt_pool_em` **只回溯最近约 3 周**的涨停池，更早的日期一律返回空。涨停基因是第一层筛选，数据缺失会直接让股池为空 —— 报告里的「数据覆盖」表会把这一点显式标出来，避免把「没数据」误读成「策略没信号」。

这意味着**现在能有效回测的窗口只有最近三周左右**。要拉长样本，只能靠实盘每天运行把快照攒进 `market_data.db`（`get_zt_pool` 已经先查快照再打接口，攒下的数据会自动被回测复用）。

## 后续优化顺序

1. 按板块建立盘前核心股池，补齐板块内核心排名。
2. 增加板块强度和持续性判断，记录四个时间点的资金切换。
3. 增加龙头相对强度、板块带动能力和第二/第三核心逻辑。
4. 区分半路、低吸和错过后的跟随机会。
5. 盘中回放：等 `market_data.db` 攒够盘中快照后，用快照重放板块确认和龙头确认。

## 数据源

本项目使用 [AkShare](https://akshare.akfamily.xyz/) 开源数据接口，不依赖任何付费API：

| 数据 | 接口 | 说明 |
|------|------|------|
| 涨停池 | `stock_zt_pool_em` | 东方财富，含所属板块 |
| 日K线 | `stock_zh_a_daily` | 新浪财经，前复权 |
| 实时行情 | `stock_zh_a_spot` | 新浪财经，全市场快照 |
| 概念板块 | `stock_board_concept_name_em` / `stock_sector_spot` | 东方财富失败时自动切换新浪 |
| 行业板块 | `stock_board_industry_name_em` / `stock_sector_spot` | 东方财富失败时自动切换新浪 |
